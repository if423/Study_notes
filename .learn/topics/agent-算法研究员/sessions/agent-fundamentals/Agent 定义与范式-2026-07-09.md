## 定位

Agent 定义与范式 是「Agent 算法研究员」知识地图中最根基的概念。如果说整个知识地图是一座大厦，这个概念就是地基——它回答的是最根本的问题：**"AI Agent 到底是什么？有哪些类型的 Agent？它们各自的运作逻辑是什么？"** 只有先建立这个全局分类框架，后续深入学习 ReAct、多 Agent 协作、规划算法等才有立足之地。

## 核心机制

### 一、AI Agent 的严格定义

在人工智能领域，**Agent（智能体）** 的完整定义包含四个要素：

> **Agent = 感知（Perceive）+ 推理（Reason）+ 决策（Decide）+ 执行（Act）**

一个系统要被称为 Agent，必须同时满足以下全部条件：

1. **自主性（Autonomy）**：能在没有人类直接干预的情况下运行，自行决定做什么、何时做。
2. **感知能力（Perception）**：能从环境中接收输入（传感器数据、文本、API 返回等），形成对当前状态的理解。
3. **反应性（Reactivity）**：能对外部环境的变化做出及时响应，而非只在预设时间点行动。
4. **主动性（Pro-activeness）**：不只被动响应，还能主动采取行动以达成目标——这是区分 Agent 和普通程序的关键特征。
5. **社会能力（Social Ability）**（可选但在多 Agent 系统中必须）：能与其他 Agent 或人类交互、通信、协作。

**重要的排除条件**：一个系统即使调用了 LLM，如果只是单次问答（输入 → 模型 → 输出），没有自主的感知-决策-执行循环，它就不是 Agent——它只是一个"LLM 调用"。Agent 的本质在于**闭环**。

### 二、五大经典 Agent 范式

以下是从简单到复杂的五种经典范式，它们构成了 AI Agent 研究的理论基石：

#### 1. 反应式 Agent（Reactive Agent / Simple Reflex Agent）

**规则**：基于**条件-动作规则（condition-action rules）**直接响应，不维护任何内部世界模型。

```
IF 感知到条件 C THEN 执行动作 A
```

**关键特征**：
- 没有记忆，没有历史状态
- 不推理未来，只处理"当下"
- 优点是极快、极简单；缺点是只能处理完全可观测的环境

**实例**：恒温器——温度低于阈值 → 开启加热；高于阈值 → 关闭。

#### 2. 模型式 Agent（Model-based Agent）

**规则**：维护一个**内部状态模型**来追踪世界中不可直接观测的部分，基于"当前感知 + 内部模型"共同决策。

**关键特征**：
- 有一个世界状态的内部表示（模型），持续更新
- 能处理**部分可观测环境**——通过模型"补全"看不到的信息
- 比反应式 Agent 更"聪明"，但模型本身可能出错（模型误差累积）

**实例**：自动驾驶中的车道保持——传感器只能看到部分路面标记，但内部模型推断出完整车道线位置。

#### 3. 目标驱动 Agent（Goal-based Agent）

**规则**：不仅知道当前状态，还知道**目标状态**。通过搜索和规划找到从当前状态到目标的行动序列。

**关键特征**：
- 需要"向前看"的能力——评估某个行动是否让你更接近目标
- 同一目标可以有不同的达成路径
- 核心困难在于**搜索空间爆炸**——可能路径太多，需要高效搜索算法

**实例**：导航系统——当前位置 → 搜索路径 → 目的地。

#### 4. 效用驱动 Agent（Utility-based Agent）

**规则**：在目标驱动的基础上，引入**效用函数（utility function）**来量化每个状态的"好坏程度"，选择**效用最大化**而非仅仅"达成目标"的行动。

**关键特征**：
- 不只是"达成目标 vs 没达成"，而是量化"多好 / 多差"
- 能处理**目标冲突**——通过效用加权做出折中
- 能处理**不确定性**——计算期望效用而非确定效用

**实例**：网约车派单系统——不只考虑"能否接到乘客"，还综合考虑距离、路况、司机评分、预期收入等多个维度的加权得分，选择综合最优的匹配。

#### 5. BDI Agent（Belief-Desire-Intention）

**规则**：这是最接近人类推理的范式，由三个独立但协作的模块组成：

| 组件 | 含义 | 本质问题 |
|---|---|---|
| **Belief（信念）** | Agent 对世界的认知（可能不完整、可能错误） | "我认为世界是什么样的？" |
| **Desire（愿望）** | Agent 想要达成的目标（可多个、可冲突） | "我想要什么？" |
| **Intention（意图）** | Agent 已承诺执行的行动计划 | "我决定做什么？" |

**BDI 推理流程**：
1. 根据 Belief 更新对世界的理解
2. 从 Desires 中选择一个或多个作为活跃目标
3. 生成多个可选 Plan，评估可行性
4. 选定一个 Plan 成为 Intention，承诺执行
5. 执行过程中持续监控——如果 Belief 变化表明当前 Intention 不再可行，则**重新规划**

**关键特征**：
- Intention 具有**持续性**——一旦承诺，会坚持执行到完成或被明确放弃
- 支持**意图重考虑（Intention Reconsideration）**——在适当时机放弃不再合理的意图
- 最接近人类"信念-愿望-意图"的心理学模型

### 三、现代 LLM Agent 的映射

当代基于大语言模型的 Agent（如 Claude Code、AutoGPT、MetaGPT）并非凭空产生——它们本质上是上述经典范式的工程实现：

| 经典范式 | 现代对应 |
|---|---|
| 反应式 Agent | 单轮 Function Calling（无状态） |
| 模型式 Agent | 带记忆系统的 Agent（维持对话历史 + 向量存储） |
| 目标驱动 Agent | ReAct / Plan-and-Execute Agent |
| 效用驱动 Agent | 带奖励模型 / Verifier 的 Agent（选择最优输出） |
| BDI Agent | 多 Agent 系统中的角色分工 Agent |

**但这并非完美映射**。LLM Agent 引入了一个根本性的变化：经典 Agent 的推理和规划是**符号化的、可验证的**；LLM Agent 的推理是**神经网络的、概率性的**。这带来了新的研究问题：幻觉（hallucination）对应 Belief 错误、推理链断裂对应 Intention 执行失败。

## 类比

把五种 Agent 范式想象成五个级别的"自动驾驶"：

- **L0 反应式 Agent**：定速巡航——速度低于设定值就加速，超过就减速。只活在当下，没有任何规划。
- **L1 模型式 Agent**：车道保持辅助——摄像头看到车道线，内部模型"补全"被遮挡的部分。
- **L2 目标驱动 Agent**：导航到目的地——"我要到北京"，搜索所有路径找到可行的。
- **L3 效用驱动 Agent**：智能路线选择——不仅"能到"，还要"最快 + 最省油 + 避开拥堵"，综合打分选最优。
- **L4 BDI Agent**：完全自动驾驶——不仅知道路况（Belief），想安全到达（Desire），还决定"现在变道超车"（Intention）；当发现前方事故时，重新评估是否该换路线（Intention Reconsideration）。

> ⚠️ 这个类比的局限：它把五个范式排成了线性升级，但现实中它们可以混合使用。一个复杂的 Agent 系统可能在不同模块使用不同范式。

## 代码示例

以下用 Python 展示五种范式的核心逻辑骨架（最小化但完整）：

```python
# ============================================================
# 范式 1: 反应式 Agent
# ============================================================
class ReactiveAgent:
    """仅基于当前感知做条件-动作映射，无状态、无记忆"""

    def __init__(self, rules: dict[str, str]):
        self.rules = rules  # {"感知条件": "动作"}

    def act(self, percept: str) -> str:
        return self.rules.get(percept, "noop")


# 示例：简单的客服路由
agent = ReactiveAgent({
    "complaint": "transfer_to_human",
    "refund_request": "check_policy",
    "greeting": "respond_with_greeting",
})
print(agent.act("complaint"))  # → transfer_to_human


# ============================================================
# 范式 2: 模型式 Agent
# ============================================================
class ModelBasedAgent:
    """维护内部状态模型，结合感知和模型做决策"""

    def __init__(self):
        self.model = {}  # 世界状态的内部表示

    def update_model(self, percept: dict):
        """用新的感知更新内部模型"""
        self.model.update(percept)
        # 关键：模型会"补全"未感知到的部分
        if "obstacle_distance" not in self.model:
            self.model["obstacle_distance"] = float("inf")  # 默认假设安全

    def act(self) -> str:
        if self.model.get("obstacle_distance", float("inf")) < 5:
            return "brake"
        return "cruise"


# ============================================================
# 范式 3: 目标驱动 Agent
# ============================================================
from collections import deque

class GoalBasedAgent:
    """搜索从当前状态到目标状态的行动序列"""

    def __init__(self, state: str, goal: str):
        self.state = state
        self.goal = goal

    def search(self, get_neighbors) -> list[str]:
        """BFS 搜索最短路径（简化版）"""
        queue = deque([[self.state]])
        visited = {self.state}

        while queue:
            path = queue.popleft()
            current = path[-1]

            if current == self.goal:
                return path  # 找到目标！

            for neighbor, _action in get_neighbors(current):
                if neighbor not in visited:
                    visited.add(neighbor)
                    queue.append(path + [neighbor])
        return []  # 无解

    def act(self, get_neighbors) -> str | None:
        plan = self.search(get_neighbors)
        return plan[1] if len(plan) > 1 else None  # 返回第一步行动


# ============================================================
# 范式 4: 效用驱动 Agent
# ============================================================
class UtilityBasedAgent:
    """不是找"能到"的路径，而是找"最好"的路径"""

    def utility(self, state: str, context: dict) -> float:
        """效用函数：量化状态的好坏 (0~1)"""
        score = 0.0
        # 多个维度加权求和
        if context.get("safety"):
            score += 0.4 * self._safety_score(state)
        if context.get("speed"):
            score += 0.3 * self._speed_score(state)
        if context.get("cost"):
            score += 0.3 * self._cost_score(state)
        return score

    def _safety_score(self, state): ...
    def _speed_score(self, state): ...
    def _cost_score(self, state): ...

    def decide(self, options: list[str], context: dict) -> str:
        """选择效用最高的选项"""
        return max(options, key=lambda opt: self.utility(opt, context))


# ============================================================
# 范式 5: BDI Agent（简化实现）
# ============================================================
class BDIAgent:
    def __init__(self):
        self.beliefs: dict = {}       # 信念集 — "我认为世界是怎样的"
        self.desires: list[str] = []  # 愿望集 — "我想要什么"
        self.intentions: list[str] = []  # 意图集 — "我决定做什么"

    def belief_revision(self, percept: dict):
        """BRF: 根据感知修正信念"""
        self.beliefs.update(percept)

    def generate_options(self) -> list[tuple[str, float]]:
        """根据 Belief + Desire 生成可选方案（含期望效用）"""
        options = []
        for desire in self.desires:
            # 检查信念中是否有阻挡此愿望的事实
            if desire not in self.beliefs.get("blockers", []):
                options.append((desire, self._estimate_utility(desire)))
        return options

    def filter(self, options) -> list[str]:
        """选择承诺执行的方案成为 Intention"""
        if not options:
            return []
        options.sort(key=lambda x: x[1], reverse=True)
        return [options[0][0]]

    def execute(self):
        """执行当前 Intentions，并持续监控是否需要重考虑"""
        for intention in self.intentions:
            # 关键检查：信念是否已变化导致此意图不再合理？
            if self._should_reconsider(intention):
                self.intentions.remove(intention)
                continue
            self._perform(intention)

    def _estimate_utility(self, desire) -> float: ...
    def _should_reconsider(self, intention) -> bool: ...
    def _perform(self, intention): ...

    def step(self, percept: dict):
        """单步 BDI 循环"""
        self.belief_revision(percept)
        options = self.generate_options()
        new_intentions = self.filter(options)
        self.intentions.extend(new_intentions)
        self.execute()
```

**代码走读**：

| 行 | 说明 |
|---|---|
| 1-14 | `ReactiveAgent`：一个字典查表器，最纯粹的"IF-THEN"模式 |
| 17-31 | `ModelBasedAgent`：关键是 `update_model()` 中的"默认补全"逻辑——Agent 对自己没感知到的事物做出假设 |
| 34-60 | `GoalBasedAgent`：核心是 `search()`——BFS 仅仅是示意，真实系统会用 A*、MCTS 等启发式搜索 |
| 63-82 | `UtilityBasedAgent`：核心是 `utility()`——多维加权函数。**效用函数的设计**本身就是整个子领域的研究课题 |
| 85-132 | `BDIAgent`：最复杂的范式，`step()` 展示了经典的 BDI 循环——信念修正→生成选项→筛选意图→执行+重考虑 |

## 常见误区

1. **"调用了 LLM 就是 Agent"** ❌
   → 单次 LLM 调用只是推理模块，缺少感知-决策-执行的闭环。Agent 必须有循环。

2. **"五种范式是排他的，只能选一种"** ❌
   → 现实系统通常是混合的。一个自动驾驶系统可能在避障模块用反应式、在路线规划用效用驱动、在高层次决策用 BDI。

3. **"BDI 已经过时了，LLM Agent 完全超越了它"** ❌
   → BDI 的 Belief-Desire-Intention 框架仍然是理解 Agent 认知结构的最佳概念工具。LLM Agent 的工程实现不同（神经网络推理替代符号推理），但概念框架仍然适用——Claude Code 的 system prompt 定义了它的 "Belief"，用户指令是 "Desire"，生成的 tool call 序列是 "Intention"。

4. **"Agent 越复杂越好"** ❌
   → 对于完全可观测的简单环境，反应式 Agent 可能比 BDI Agent 更好——更快、更可靠、没有模型误差累积的问题。选择什么范式取决于环境特性。

## 快速总结

- **Agent 的唯一定义**：自主的感知→推理→决策→执行闭环，而非单次模型调用
- **五大范式**是人类设计智能系统的基本蓝图：反应式（快但蠢）→ 模型式（有记忆）→ 目标驱动（会规划）→ 效用驱动（会权衡）→ BDI（会承诺和反思）
- **现代 LLM Agent 不是替代经典范式，而是用神经网络实现了它们**——理解经典范式能帮你更好地设计 LLM Agent 架构
- **选择什么范式取决于环境**：完全可观测用反应式，部分可观测用模型式，复杂目标用 BDI
