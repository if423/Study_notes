## 定位

ReAct 模式是连接「经典 Agent 范式」与「现代 LLM Agent 工程实现」的**核心桥梁**。上一讲我们学了五大范式（反应式→BDI），ReAct 就是那个让 LLM 真正跑起来的具体算法——它将推理（Reasoning）和行动（Acting）交织在一起，让模型不再是"想完再做"或"只做不想"，而是**边想边做、边做边调整**。

---

## 核心机制

### 一、论文溯源与严格定义

ReAct（**Re**asoning + **Act**ing）由 Yao et al. 在 2022 年提出（论文：*ReAct: Synergizing Reasoning and Acting in Language Models*）。其严格定义如下：

> **ReAct = 思维（Thought）→ 行动（Action）→ 观察（Observation）的交替循环，且推理步骤和行动步骤在同一个轨迹中交错出现**

这个定义的完整形式是一个**交错序列**：

```
Thought₁ → Action₁ → Observation₁ → Thought₂ → Action₂ → Observation₂ → ... → Final Answer
```

### 二、为什么需要 ReAct？（三种模式的对比）

要理解 ReAct 的价值，必须对比三种决策范式：

#### 模式 A：纯推理（Reasoning-Only，即 Chain-of-Thought）

```
问题 → Thought₁ → Thought₂ → ... → Thoughtₙ → 最终答案
```

**规则**：模型只生成内部思考，不能与外部环境交互。

**致命缺陷**：Thought 中包含的事实错误（幻觉）无法被纠正——模型可能在错误的假设上推导一整条链，最终输出一个看似自洽但完全错误的答案。"一个谎言推导出一整套谎言体系"。

#### 模式 B：纯行动（Acting-Only）

```
问题 → Action₁ → Observation₁ → Action₂ → Observation₂ → ... → 最终答案
```

**规则**：模型只执行行动并观察结果，但不显式记录中间推理。

**致命缺陷**：没有推理轨迹，不知道"为什么选择了这个行动"。当行动失败时，无法回溯思考原因，只能盲目重试。

#### 模式 C：ReAct（推理+行动交错）

```
问题 → Thought₁ → Action₁ → Observation₁ → Thought₂ → Action₂ → ...
```

**规则**：每一步行动前都有一段显式推理，每一步观察后都重新评估推理。

**优势**：Thought 提供了**可解释性**和**纠错机会**——当 Observation 与预期不符时，下一个 Thought 可以识别矛盾并调整策略。

**一个具体对比**（问答任务 "2023 年诺贝尔物理学奖得主是谁？"）：

| 纯推理（CoT） | ReAct |
|---|---|
| Thought: 我记得 2023 年物理奖是研究阿秒物理的 | Thought: 我需要查证 2023 年诺贝尔物理学奖得主 |
| Thought: 得主应该是 Pierre Agostini, Ferenc Krausz, Anne L'Huillier | Action: search("2023 Nobel Prize Physics winner") |
| → **如果记错了，错误不可逆** | Observation: Pierre Agostini, Ferenc Krausz, Anne L'Huillier |
| | Thought: 搜索结果确认是这三位，理由是他们研究物质中电子动力学的阿秒脉冲实验方法 |
| | Final Answer: ... ✅ **基于真实数据** |

### 三、ReAct 循环的完整规则

ReAct 的每一步必须严格遵循以下规则：

```
1. 接收当前状态（问题 + 历史 Observation 序列）
2. 生成 Thought：分析当前已知信息，推理下一步该做什么
3. 生成 Action：基于 Thought，产出具体的可执行动作
4. 执行 Action：将 Action 发送到环境（工具/API/搜索引擎等）
5. 接收 Observation：环境返回结果
6. 判断终止条件：
   - 如果信息足够 → 生成 Final Answer，退出循环
   - 如果信息不足 → 回到步骤 2，继续循环
7. （隐式约束）最大步数限制：防止无限循环
```

**关键约束**：

- **Thought 和 Action 的分离是硬性的**——Thought 是内部推理（不执行），Action 是外部操作（执行后返回观察）。混淆两者会导致"对着空气执行"或"把内部想法当成行动结果"。
- **Observation 来自外部环境，绝不能由模型自己编造**——这是 LLM Agent 中最常见的错误：模型生成了一个 Tool Call 但没有真正执行，却凭空生成了一个"看起来合理"的结果。ReAct 的正确实现必须确保 Observation 来自真实的工具返回。
- **上下文的累积性**——每一步的 Thought-Action-Observation 全部追加到上下文中，构成"工作记忆"。这意味着（1）上下文窗口会持续增长，（2）早期的错误 Thought 如果不被纠正会持续污染后续推理。

### 四、ReAct 与传统范式的对应关系

将 ReAct 映射回上一讲的五大范式：

| ReAct 组件 | 对应的经典范式特征 |
|---|---|
| Observation → 更新推理 | 模型式 Agent（内部状态更新） |
| Thought → 分析是否接近目标 | 目标驱动 Agent（评估进展） |
| 选择 Action 时的权衡 | 效用驱动 Agent（选最优行动） |
| Thought 中反思和调整 | BDI Agent（Intention Reconsideration） |

ReAct 不是某一个范式的实现，而是**在 LLM 中集成了所有五种范式的关键要素**。

### 五、ReAct 的变体与扩展

自 2022 年原始论文以来，ReAct 衍生出多个变体：

| 变体 | 核心改进 | 适用场景 |
|---|---|---|
| **Self-Ask** | 将 Thought 拆分为 Follow-up Question → Intermediate Answer | 多跳推理 |
| **IRCoT** | 交织检索（Retrieval）和 CoT，每一步推理前先检索 | 知识密集型任务 |
| **Reflexion** | 在 ReAct 循环外增加"反思层"——完成任务后进行全局评价 | 需要自我改进的任务 |
| **ReWOO** | 将 Plan 和 Execution 分离——先全局规划再批量执行 | 降低推理开销 |
| **Plan-and-Solve** | 先生成完整计划，再按 ReAct 逐步执行，计划可动态调整 | 复杂多步任务 |

## 类比

把 ReAct 想象成**厨师按照食谱做菜，但食谱是自己边做边写的**：

- **纯推理**：凭记忆写一份完整的烹饪步骤，然后不看厨房、不尝味道，直接端出"想象中的菜"——实际可能忘了放盐。
- **纯行动**：疯狂切菜、倒油、翻炒——速度快，但没人知道下一步该干嘛，可能糖当成盐。
- **ReAct**：看一眼食材（Observation），想一下"先焯水去腥"（Thought），执行焯水（Action），尝一下汤（Observation），想"咸度不够"（Thought），加半勺盐（Action），再尝（Observation），想"完美了"（Thought），出锅（Final Answer）。

> ⚠️ 这个类比的局限：厨师有物理直觉和肌肉记忆，不需要显式写出 Thought；而 LLM 必须显式生成每个 Thought 才能"记住"自己的推理——不生成 Thought 就意味着模型在那个时间步没有推理能力。

## 代码示例

以下是一个完整的 ReAct Agent Python 实现，模拟一个能使用搜索和计算工具的智能体：

```python
"""
ReAct Agent — Reasoning + Acting 交替循环的完整实现
参考: Yao et al. 2022, "ReAct: Synergizing Reasoning and Acting in Language Models"
"""

import re
from dataclasses import dataclass, field


# ============================================================
# 1. 工具定义
# ============================================================
@dataclass
class Tool:
    """工具：Agent 可执行的外部操作"""
    name: str
    description: str
    func: callable


def search(query: str) -> str:
    """模拟搜索引擎（实际项目中使用真实 API）"""
    knowledge_base = {
        "2023 nobel physics": "2023年诺贝尔物理学奖授予 Pierre Agostini、Ferenc Krausz 和 Anne L'Huillier，表彰他们为研究物质中电子动力学而产生阿秒光脉冲的实验方法。",
        "python 3.12 release": "Python 3.12 于 2023 年 10 月 2 日发布，主要新特性包括更友好的错误消息、f-string 语法改进、类型参数语法支持等。",
    }
    key = query.lower().strip()
    return knowledge_base.get(key, f"未找到关于 '{query}' 的信息。")


def calculate(expression: str) -> str:
    """安全计算器（eval 仅用于演示，生产环境使用 AST 解析）"""
    try:
        allowed = set("0123456789+-*/().%^ ")
        if not all(c in allowed for c in expression):
            return "错误：表达式包含不允许的字符"
        return str(eval(expression))
    except Exception as e:
        return f"计算错误: {e}"


# ============================================================
# 2. ReAct Agent 核心
# ============================================================
@dataclass
class ReActAgent:
    """
    ReAct Agent 核心循环

    规则：
    1. 每一步必须先生成 Thought，再生成 Action
    2. Action 由外部环境执行，返回 Observation
    3. Observation 不能由模型编造 —— 必须来自真实工具返回
    4. 达到 max_steps 或触发 Finish 时终止
    """
    tools: dict[str, Tool]
    max_steps: int = 10
    history: list[dict] = field(default_factory=list)

    def _build_prompt(self, question: str) -> str:
        """构建系统 Prompt（定义了 ReAct 的语法规则）"""
        tool_descriptions = "\n".join(
            f"- {t.name}: {t.description}" for t in self.tools.values()
        )
        return f"""你是一个能使用工具的智能助手。严格遵循以下格式回答：

可用工具：
{tool_descriptions}

回答格式（每行一个标记，不可混用）：
Thought: <你的内部推理——分析已知信息，推理下一步该做什么>
Action: <工具名>[<工具输入>]
Observation: <工具执行结果——由系统填入，你不要编造>

当你获得足够信息来回答问题时，使用：
Thought: 我现在有足够信息回答问题
Finish: <最终答案>

当前问题：{question}
"""

    def _parse_response(self, response: str) -> tuple[str | None, str | None, str | None]:
        """解析 LLM 响应，提取 Thought / Action / Finish"""
        thought = None
        action_name = None
        action_input = None
        finish = None

        for line in response.strip().split("\n"):
            line = line.strip()
            if line.lower().startswith("thought:"):
                thought = line.split(":", 1)[1].strip()
            elif line.lower().startswith("finish:"):
                finish = line.split(":", 1)[1].strip()
            elif line.lower().startswith("action:"):
                action_str = line.split(":", 1)[1].strip()
                match = re.match(r"(\w+)\[(.*)\]", action_str)
                if match:
                    action_name = match.group(1)
                    action_input = match.group(2)

        return thought, action_name, action_input, finish

    def _execute_action(self, action_name: str, action_input: str) -> str:
        """执行 Action——返回真实的 Observation，绝不编造"""
        tool = self.tools.get(action_name)
        if tool is None:
            return f"错误：未知工具 '{action_name}'。可用工具：{list(self.tools.keys())}"
        return tool.func(action_input)

    def run(self, question: str, llm_call: callable) -> str:
        """
        ReAct 主循环

        参数:
            question: 用户问题
            llm_call: LLM 调用函数，签名为 (prompt: str) -> str
                      （在实际项目中替换为 OpenAI/Anthropic API 调用）

        返回:
            Agent 的最终答案
        """
        prompt = self._build_prompt(question)
        self.history = []

        for step in range(1, self.max_steps + 1):
            # 步骤 1-2: 调用 LLM 生成 Thought + Action
            response = llm_call(prompt)
            thought, action_name, action_input, finish = self._parse_response(response)

            if finish:
                self.history.append({"step": step, "type": "finish", "content": finish})
                return finish

            if action_name is None:
                # LLM 没有生成有效的 Action——这本身是一个信号
                prompt += (
                    f"\n{response}\n"
                    "Observation: 你没有生成有效的 Action。请使用 Action: 工具名[输入] 格式。\n"
                )
                continue

            # 步骤 3-5: 执行 Action → 获取 Observation
            observation = self._execute_action(action_name, action_input)

            # 步骤 6: 记录并追加到上下文
            self.history.append({
                "step": step,
                "thought": thought,
                "action": f"{action_name}[{action_input}]",
                "observation": observation,
            })

            # 关键：Observation 追加到 prompt，不替换
            prompt += (
                f"\nThought: {thought}\n"
                f"Action: {action_name}[{action_input}]\n"
                f"Observation: {observation}\n"
            )

        # 达到最大步数仍未 Finish
        return "未能找到答案：达到最大推理步数限制。"


# ============================================================
# 3. 模拟 LLM 调用（用于演示；实际项目替换为真实 API）
# ============================================================
def simulated_llm(prompt: str) -> str:
    """
    模拟 LLM 响应——基于固定模式生成 Thought + Action/Finish。
    真实项目中替换为：
        import anthropic
        client = anthropic.Anthropic()
        response = client.messages.create(
            model="claude-sonnet-4-20250514",
            messages=[{"role": "user", "content": prompt}],
        )
        return response.content[0].text
    """
    history_lines = prompt.count("Observation:")
    is_first = (history_lines == 0)

    if is_first:
        # 第一步：搜索
        if "2023" in prompt and "诺贝尔" in prompt:
            return (
                "Thought: 用户询问2023年诺贝尔物理学奖得主，我需要搜索最新信息而非依赖训练数据。\n"
                "Action: search[2023 nobel physics]"
            )
        elif "37 * 15" in prompt or "计算" in prompt:
            return (
                "Thought: 这是一个数学计算问题，我应该使用计算器工具得出精确结果。\n"
                "Action: calculate[37 * 15 + 128]"
            )
        else:
            return (
                "Thought: 我需要搜索相关信息来回答这个问题。\n"
                "Action: search[" + prompt.split("当前问题：")[-1].strip() + "]"
            )
    else:
        # 后续步骤：检查是否信息充足
        if "Observation:" in prompt and "2023年诺贝尔" in prompt:
            return (
                "Thought: 搜索返回了完整的诺贝尔奖信息，我现在可以给出准确答案。\n"
                "Finish: 2023年诺贝尔物理学奖授予 Pierre Agostini、Ferenc Krausz 和 Anne L'Huillier，"
                "表彰他们在阿秒光脉冲实验方法上的贡献。"
            )
        elif "Observation:" in prompt and "555" in prompt:
            return (
                "Thought: 计算器返回了 683，这是一个精确结果，无需进一步验证。\n"
                "Finish: 37 × 15 + 128 = 683"
            )
        else:
            return (
                "Thought: 搜索结果不足以完整回答问题，我需要换个角度再搜索一次。\n"
                "Action: search[2023 Nobel Prize physics winner]"
            )


# ============================================================
# 4. 运行演示
# ============================================================
if __name__ == "__main__":
    agent = ReActAgent(
        tools={
            "search": Tool("search", "搜索互联网获取最新信息", search),
            "calculate": Tool("calculate", "执行数学计算", calculate),
        },
        max_steps=5,
    )

    print("=" * 60)
    print("问题 1: 2023年诺贝尔物理学奖得主是谁？")
    print("=" * 60)
    answer = agent.run("2023年诺贝尔物理学奖得主是谁？", simulated_llm)
    print(f"\n✅ 最终答案: {answer}")
    print(f"\n📊 推理轨迹 ({len(agent.history)} 步):")
    for h in agent.history:
        print(f"  步骤 {h['step']}: {h.get('thought', '')[:40]}...")
        if 'observation' in h:
            print(f"    观察: {h['observation'][:50]}...")

    print("\n" + "=" * 60)
    print("问题 2: 37 × 15 + 128 = ?")
    print("=" * 60)
    agent2 = ReActAgent(
        tools={
            "search": Tool("search", "搜索互联网获取最新信息", search),
            "calculate": Tool("calculate", "执行数学计算", calculate),
        },
        max_steps=5,
    )
    answer2 = agent2.run("37 × 15 + 128 = ?", simulated_llm)
    print(f"\n✅ 最终答案: {answer2}")
```

**代码走读**：

| 模块 | 行 | 说明 |
|---|---|---|
| `Tool` | 22-26 | 工具的数据结构——`name` 供 LLM 识别，`description` 写入 Prompt，`func` 是实际执行函数 |
| `ReActAgent.__init__` | 45-49 | `max_steps` 是安全阀——防止 Agent 陷入无限搜索循环（ReAct 论文建议通常 5-10 步） |

| `simulated_llm` | 148-189 | 模拟 LLM 用于演示——真实项目中替换为 Anthropic/OpenAI API 调用，注释中已给出参考代码 |

**将 `simulated_llm` 替换为真实 API 的关键代码**：

```python
import anthropic

def real_llm(prompt: str) -> str:
    client = anthropic.Anthropic()
    response = client.messages.create(
        model="claude-sonnet-4-20250514",
        max_tokens=1024,
        system="你是一个严格遵循 ReAct 格式的智能助手。",
        messages=[{"role": "user", "content": prompt}],
    )
    return response.content[0].text
```

## 常见误区

1. **"Observation 由模型自己编就行"** ❌
   这是 LLM Agent 中最危险的错误。模型可能生成一个貌似合理的 Observation（称为 hallucinated observation），然后基于这个虚假信息推导。**Observation 必须来自工具的真实返回**——`_execute_action()` 的返回值，绝不能由模型文本生成。

2. **"Thought 可有可无"** ❌
   去掉 Thought 就退化为纯行动模式。Thought 不仅提供可解释性，更关键的是它为 LLM 创造了"草稿空间"——模型在生成下一个 token 时能看到自己的 Thought，这相当于给了它一个"短期记忆"来引导后续推理。

3. **"ReAct 只适用于搜索类任务"** ❌
   ReAct 适用于任何需要外部交互的任务：代码执行（Tool Call）、数据库查询、文件操作、API 调用、浏览器自动化——只要"想一步 + 做一步 + 看一步"的循环有意义。

4. **"max_steps 设大一点更安全"** ❌
   更大的 max_steps 不等于更安全——它意味着更长的上下文（可能超出窗口）、更高的 token 消耗、更多的错误累积机会。**关键不是步数上限，而是 Termination 条件的敏感性**——Agent 能否在信息充足时及时终止。

## 快速总结

- **ReAct = Thought → Action → Observation 的交替循环**，将推理和行动交织在同一轨迹中
- **核心价值**：可解释性（Thought 展示推理过程）+ 可纠错性（Observation 可以修正错误推理）+ 可交互性（与外部世界实时交互）
- **Observation 必须来自真实工具返回**——这是 ReAct 实现中最容易犯错的关键点
- **ReAct 是连接经典 Agent 范式与现代 LLM Agent 的桥梁**——它在 LLM 中集成了模型式、目标驱动、效用驱动和 BDI 的关键特征
