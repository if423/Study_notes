## 定位

如果说 Agent 定义与范式是"Agent 的分类学"、ReAct 模式是"LLM Agent 的具体算法"，那么**感知-规划-执行循环就是所有 Agent 共有的骨骼**——从恒温器到自动驾驶，从 AutoGPT 到 Claude Code，无论简单还是复杂、符号还是神经网络，每一个 Agent 都在这三个阶段的循环中运转。它不是某个具体的算法，而是一个**元模式（meta-pattern）**：所有 Agent 架构都是它的特化实现。

---

## 核心机制

### 一、严格定义

感知-规划-执行循环（Sense-Plan-Act Loop，简称 SPA 循环）的严格定义：

> **Agent 在时间轴上重复执行三个不可再分解的阶段：感知环境状态 → 基于目标和状态规划行动 → 执行行动并改变环境，形成一个闭环。三个阶段的输出分别是：世界状态（World State）、行动计划（Plan）、环境反馈（Feedback）。**

用形式化语言描述：

```
给定 Agent A 和环境 E，在时间步 t：
  1. Sense:  s_t = perceive(E_t)          → 从环境获取原始观测，生成状态表示
  2. Plan:   a_t = policy(s_t, G)         → 基于当前状态和目标，决定行动
  3. Act:    E_{t+1} = execute(a_t, E_t)  → 执行行动，环境进入新状态
  4. 反馈闭环：E_{t+1} 成为下一轮 t+1 的输入
```

### 二、三个阶段的逐层拆解

#### 阶段 1：感知（Sense）— "我看到什么？"

感知阶段必须解决三个子问题：

**1a. 原始信号采集**
从环境中获取原始数据。来源可以是被动传感器（摄像头、麦克风、API 响应），也可以是主动查询（数据库搜索、HTTP 请求）。

**1b. 信号到状态的转换（State Estimation）**
这是感知阶段最核心也最困难的部分。原始信号不是状态——摄像头输出像素矩阵，但 Agent 需要的状态是"前方 30 米处有一辆红色轿车以 60km/h 接近"。这个转换过程的正式名称是**状态估计（State Estimation）**。

**1c. 处理部分可观测性（Partial Observability）**
在绝大多数真实环境中，Agent 无法获取完整的世界状态。你只能看到世界的一部分，其余必须推断。这就是**部分可观测马尔可夫决策过程（POMDP）**所建模的场景。

处理策略：
- **维护信念状态（Belief State）**：不是"环境是什么"，而是"我有多大概率认为环境是什么"——这是 BDI 中 Belief 的来源
- **主动信息获取**：如果当前信息不足以决策，下一步规划可以优先"获取更多信息"而非"直接解决问题"
- **默认假设**：对未观测到的部分使用安全默认值（如前两讲 ModelBasedAgent 中的 `float("inf")`）

#### 阶段 2：规划（Plan）— "我该怎么做？"

规划阶段根据感知到的状态，生成行动策略。这可以是从极简到极复杂的连续谱：

| 复杂度 | 规划方式 | 对应 Agent 类型 | 实例 |
|---|---|---|---|
| 最低 | 条件-动作映射（无搜索） | 反应式 Agent | `if obstacle: brake` |
| 低 | 当前状态 + 目标 → 单步最优 | 效用驱动 Agent | `max(options, key=utility)` |
| 中 | 有限步数前瞻搜索 | 目标驱动 Agent | BFS/A* 搜索路径 |
| 高 | 层次化任务分解 + 动态重规划 | BDI Agent | 先拆子目标，再逐步执行 |
| 最高 | 开放式推理 + 工具编排 | LLM Agent (ReAct) | Thought → Action → Observation |

**规划质量的三个衡量维度**：
- **完备性（Completeness）**：如果存在解，规划能否找到？
- **最优性（Optimality）**：找到的解是否在某个度量下最优？
- **实时性（Real-time）**：能否在时间约束内给出决策？（自动驾驶中，1 秒的规划延迟 = 不可接受）

这三者互相制约——追求最优往往牺牲实时性，追求实时往往牺牲完备性。

#### 阶段 3：执行（Act）— "动手！"

执行阶段将规划阶段产出的行动付诸实施。这个阶段看似简单，但包含三个关键子问题：

**3a. 行动粒度的选择**
行动可以是不同粒度的：
- **原语动作（Primitive Action）**：`move_left()`, `pick_up(obj)`, `call_api(endpoint, params)`
- **宏动作 / 技能（Macro Action / Skill）**：`navigate_to(location)`, `login_and_fetch()`, `write_and_test_code(requirement)`
- **子 Agent 调用**：将整个子任务委托给另一个 Agent

选择什么粒度取决于规划能力——LLM Agent 天然倾向于高层宏动作，符号 Agent 更擅长原语动作的精确搜索。

**3b. 执行监控（Execution Monitoring）**
行动不总是按预期完成。执行监控在行动执行期间持续检查：
- 行动是否成功启动？
- 行动是否在预期时间内完成？
- 中间结果是否偏离预期？

检测到异常 → 触发**中断和重规划**。

**3c. 行动效果的验证**
行动执行后，必须通过下一轮感知来验证效果——这就是**反馈闭环**。

### 三、反馈闭环：区分"循环"和"流水线"

很多人把 SPA 误解为线性流水线（感知一次 → 规划一次 → 执行一次 → 结束），但 SPA 的关键在**循环**二字。反馈闭环是 SPA 的生命线：

```
                ┌──────────────────────────────────┐
                │         反馈闭环                   │
                │  "上次行动到底产生了什么效果？"     │
                │                                    │
    ┌──────┐   ▼   ┌──────┐   ▼   ┌──────┐   │
    │ Sense│──────▶│ Plan │──────▶│ Act  │───┘
    └──────┘       └──────┘       └──────┘
        ▲                                        │
        └────────────────────────────────────────┘
                新状态触发下一轮感知
```

**反馈闭环的三个关键功能**：

1. **误差修正**：如果行动效果偏离预期，下一轮规划可以调整。这不依赖规划阶段自身的完美性。
2. **动态环境适应**：环境在 Agent 行动期间可能独立变化（其他 Agent 的行动、自然事件）。反馈闭环让 Agent 能看到这些变化。
3. **学习机会**：观察"我预期 X → 实际发生 Y"的差距，是 Agent 学习和改进的基础信号。

### 四、SPA 与 ReAct 和经典范式的映射

SPA 是一切的总纲——把 SPA 套到前两讲的概念上：

| SPA 阶段 | 经典范式中的体现 | ReAct 中的体现 |
|---|---|---|
| **Sense** | 反应式的 `percept`、模型式的 `update_model`、BDI 的 `belief_revision` | `Observation`（工具返回值） |
| **Plan** | 目标驱动的 `search()`、效用驱动的 `decide()`、BDI 的 `generate_options` + `filter` | `Thought`（推理下一步该做什么） |
| **Act** | 所有范式中的执行函数 | `Action`（工具调用） |
| **反馈闭环** | BDI 的 `_should_reconsider` | 下一轮 Observation 与预期对比 |

**ReAct 本质上就是 SPA 循环在 LLM 上的一个 Prompt 工程实现**——用文本格式（Thought → Action → Observation）来驱动 LLM 完成感知-规划-执行的每一轮迭代。

## 类比

把 SPA 循环想象成**外卖骑手的送餐过程**：

- **Sense（感知）**：看一眼手机上的订单详情——取餐地址、送餐地址、顾客备注（别放辣）。
- **Plan（规划）**：脑中形成路线——先去 A 餐厅取餐 → 滨河路正在堵绕过 → 预计 18 分钟送达。
- **Act（执行）**：骑车上路。
- **反馈闭环**：骑到一半发现封路施工 → **重新 Sense**（观察当前路况）→ **重新 Plan**（换一条路）→ **重新 Act**（拐进小巷）。

一个优秀的骑手和一个糟糕的骑手的核心差距不在 Act（都会骑车），而在反馈闭环的速度和质量——优秀的骑手封路后 5 秒就调整路线，糟糕的骑手封路后停在那发呆 2 分钟。

> ⚠️ 这个类比的局限：外卖骑手的 Sense 非常丰富（视觉、听觉、经验直觉），而 AI Agent 的 Sense 高度受限——只有被显式编程的传感器和 API。骑手能在封路时无缝切换策略，Agent 却可能因为"封路"这个 Observation 不在预期格式中而崩溃。

## 代码示例

以下是一个完整的 SPA 循环框架，然后展示三种不同复杂度的实现：

```python
"""
感知-规划-执行（SPA）循环 —— 所有 Agent 的元模式
从简单到复杂三种实现，展示 SPA 的通用性和可扩展性
"""

from abc import ABC, abstractmethod
from dataclasses import dataclass, field
from collections import deque
import random
import time


# ============================================================
# 1. SPA 循环的抽象框架
# ============================================================
@dataclass
class Environment:
    """环境：Agent 所处的外部世界。Agent 只能通过感知和行动与之交互。"""
    state: dict

    def apply(self, action: str) -> dict:
        """执行行动，返回新的环境状态和反馈"""
        raise NotImplementedError


@dataclass
class Percept:
    """感知结果：从环境采集的原始信号及其转换后的状态表示"""
    raw: dict              # 原始信号
    estimated_state: dict  # 状态估计结果
    timestamp: float       # 感知时间戳


class SPAAgent(ABC):
    """SPA Agent 抽象基类 —— 定义 SPA 循环的通用骨架"""

    def __init__(self, env: Environment, max_iterations: int = 100):
        self.env = env
        self.max_iterations = max_iterations
        self.history: list[dict] = []

    # --- 三个抽象方法，子类必须实现 ---

    @abstractmethod
    def sense(self) -> Percept:
        """阶段 1: 感知 —— 从环境获取信号并转换为状态表示"""
        ...

    @abstractmethod
    def plan(self, percept: Percept) -> str:
        """阶段 2: 规划 —— 基于当前状态决定行动"""
        ...

    @abstractmethod
    def act(self, action: str) -> dict:
        """阶段 3: 执行 —— 将行动施加到环境，获取反馈"""
        ...

    # --- SPA 主循环（模板方法 —— 子类不应覆盖） ---

    def run(self) -> list[dict]:
        """SPA 主循环：Sense → Plan → Act → 反馈闭环 → 重复"""
        for iteration in range(self.max_iterations):
            # 阶段 1: 感知
            percept = self.sense()

            # 阶段 2: 规划
            action = self.plan(percept)

            # 破局条件：规划阶段决定"不需要行动"
            if action == "STOP":
                self.history.append({
                    "iteration": iteration,
                    "state": percept.estimated_state,
                    "action": "STOP",
                    "reason": "目标达成或无法继续",
                })
                break

            # 阶段 3: 执行
            feedback = self.act(action)

            # 记录历史（反馈闭环的数据基础）
            self.history.append({
                "iteration": iteration,
                "state": percept.estimated_state,
                "action": action,
                "feedback": feedback,
            })

        return self.history


# ============================================================
# 2. 实现一：反应式 SPA Agent（感知→查表→执行，无规划搜索）
# ============================================================
class ReactiveSPAAgent(SPAAgent):
    """
    反应式 SPA：Plan 阶段只是查表。
    对应经典范式：反应式 Agent。

    SPA 在这里表现为：
      Sense: 读传感器 → Plan: 查规则表 → Act: 执行动作 → 反馈闭环
    """

    def __init__(self, env, rules: dict[str, str]):
        super().__init__(env)
        self.rules = rules

    def sense(self) -> Percept:
        """感知：直接读取环境状态（假设完全可观测）"""
        return Percept(
            raw=self.env.state,
            estimated_state=self.env.state.copy(),
            timestamp=time.time(),
        )

    def plan(self, percept: Percept) -> str:
        """规划 = 查规则表（最简单的 Plan）"""
        state_str = str(percept.estimated_state.get("condition", ""))
        return self.rules.get(state_str, "STOP")

    def act(self, action: str) -> dict:
        """执行：将行动反馈到环境"""
        return self.env.apply(action)


# ============================================================
# 3. 实现二：搜索式 SPA Agent（感知→BFS搜索→执行，含重规划）
# ============================================================
class SearchSPAAgent(SPAAgent):
    """
    搜索式 SPA：Plan 阶段进行前瞻搜索。
    对应经典范式：目标驱动 Agent。

    SPA 在这里表现为：
      Sense: 估计当前状态 → Plan: BFS搜索行动序列 → Act: 执行第一步
      → 反馈闭环: 如果执行偏离预期 → 下一轮重规划
    """

    def __init__(self, env, goal: str):
        super().__init__(env)
        self.goal = goal
        self.current_plan: list[str] = []      # 当前计划队列
        self.expected_state: dict | None = None # 执行后预期的状态

    def sense(self) -> Percept:
        """感知：读取环境 + 对比预期（反馈闭环的检查点）"""
        actual_state = self.env.state.copy()

        # 反馈闭环核心逻辑：
        # 如果实际状态与预期不符 → 清空当前计划（下一轮会触发重规划）
        if self.expected_state and actual_state != self.expected_state:
            self.current_plan = []  # 废弃旧计划

        return Percept(
            raw=self.env.state,
            estimated_state=actual_state,
            timestamp=time.time(),
        )

    def plan(self, percept: Percept) -> str:
        """规划：如果没有有效计划 → 搜索新计划"""
        if self.current_plan:
            # 已有计划且仍然有效 → 直接执行下一步
            return self.current_plan.pop(0)

        # 需要规划：BFS 搜索从当前状态到目标的路径
        self.current_plan = self._bfs_search(
            percept.estimated_state, self.goal
        )

        if not self.current_plan:
            return "STOP"  # 搜索失败，无法达成目标

        return self.current_plan.pop(0)

    def _bfs_search(self, start: dict, goal: str) -> list[str]:
        """BFS 搜索最短行动序列（简化示例）"""
        transitions = {
            "A": [("B", "goto_B"), ("C", "goto_C")],
            "B": [("D", "goto_D"), ("A", "goto_A")],
            "C": [("D", "goto_D")],
            "D": [],
        }
        queue = deque([(start.get("position", "A"), [])])
        visited = {start.get("position", "A")}

        while queue:
            current, path = queue.popleft()
            if current == goal:
                return path

            for neighbor, action in transitions.get(current, []):
                if neighbor not in visited:
                    visited.add(neighbor)
                    queue.append((neighbor, path + [action]))
        return []

    def act(self, action: str) -> dict:
        """执行：行动前记录预期状态（供下一轮 sense 对比）"""
        if action.startswith("goto_"):
            target = action.split("_")[1]
            self.expected_state = {"position": target}
        else:
            self.expected_state = None
        return self.env.apply(action)

# 4. 实现三：LLM 驱动的 SPA Agent（Sense→Prompt→LLM Plan→Act）
# ============================================================
class LLMSPAAgent(SPAAgent):
    """
    LLM 驱动的 SPA：Plan 阶段调用 LLM 生成行动。
    这就是 ReAct 的底层框架 —— ReAct 本质上就是 LLMSPAAgent 的一个具体实例。

    SPA 在这里表现为：
      Sense: 工具返回 + 历史 → Plan: LLM 推理 → Act: Tool Call → 反馈闭环
    """

    def __init__(self, env, tools: dict, llm_call: callable):
        super().__init__(env)
        self.tools = tools
        self.llm_call = llm_call
        self.context: list[dict] = []  # 累积的感知-行动历史

    def sense(self) -> Percept:
        """感知：从积累的上下文构建当前状态表示"""
        return Percept(
            raw={"context_length": len(self.context)},
            estimated_state={
                "history": self.context.copy(),
                "env_state": self.env.state,
            },
            timestamp=time.time(),
        )

    def plan(self, percept: Percept) -> str:
        """规划：调用 LLM 进行推理和行动决策"""
        prompt = self._build_prompt(percept)
        response = self.llm_call(prompt)
        return self._parse_action(response)

    def _build_prompt(self, percept: Percept) -> str:
        """将 SPA 的 Plan 阶段转化为 Prompt（这正是 ReAct 的 Prompt 设计）"""
        history_text = "\n".join(
            f"Step {h['step']}: Action={h['action']}, Result={h['result']}"
            for h in percept.estimated_state["history"][-5:]  # 窗口限制
        )
        return f"""基于以下历史，决定下一步行动：

历史记录（最近 5 步）：
{history_text}

当前环境状态：{percept.estimated_state['env_state']}

可用工具：{list(self.tools.keys())}

请以格式 "ACTION: <工具名> <参数>" 回复，或 "ACTION: STOP" 结束。"""

    def _parse_action(self, response: str) -> str:
        """解析 LLM 输出为可执行的动作"""
        for line in response.strip().split("\n"):
            if line.strip().upper().startswith("ACTION:"):
                return line.split(":", 1)[1].strip()
        return "STOP"

    def act(self, action: str) -> dict:
        """执行：调用工具，记录结果到上下文（反馈闭环的数据累积）"""
        if action == "STOP":
            return {"status": "stopped"}

        parts = action.split(maxsplit=1)
        tool_name = parts[0]
        tool_input = parts[1] if len(parts) > 1 else ""

        tool_func = self.tools.get(tool_name)
        if tool_func is None:
            result = f"错误：未知工具 '{tool_name}'"
        else:
            result = tool_func(tool_input)

        # 关键：记录到累积上下文（反馈闭环）
        step_num = len(self.context) + 1
        self.context.append({
            "step": step_num, "action": action, "result": result
        })

        # 同时更新环境
        return self.env.apply(action)

    print(f"规划次数: {len([h for h in search.history if h.get('action', '').startswith('goto')])}")

    def simulated_llm(prompt: str) -> str:
        step_counter[0] += 1
        # 模拟一个简单的策略：按顺序移动 A→B→C→D
        moves = ["ACTION: goto B", "ACTION: goto C", "ACTION: goto D", "ACTION: STOP"]
        idx = min(step_counter[0] - 1, 3)
        return moves[idx]

    llm_agent = LLMSPAAgent(
        env3,
        tools={
            "goto": lambda x: f"Moved to {x}",
            "search": lambda q: f"Search result for '{q}'",
        },
        llm_call=simulated_llm,
    )
    llm_agent.run()
    print(f"最终位置: {env3.state['position']}")
    print(f"LLM 调用次数: {step_counter[0]}")
    print(f"上下文累积: {len(llm_agent.context)} 步")
```

## 常见误区

1. **"SPA 的三个阶段是等权重的"** ❌
   不同 Agent 在三阶段上分配的计算资源差异巨大。反应式 Agent 的 Plan 几乎为零；LLM Agent 的 Plan 可能占 90% 的时间/Token。**核心瓶颈在哪取决于架构，不是 SPA 本身。**

2. **"SPA 必须是同步的、阻塞的"** ❌
   SPA 的三个阶段可以并行化。例如：执行 Action_A 的同时感知环境变化、规划 Action_C 的同时执行 Action_B。这叫做**流水线 SPA（Pipelined SPA）**。现代实时 Agent 系统几乎都是流水线化的。

3. **"Sense 就是读传感器，Plan 就是跑算法，Act 就是调用函数——没啥好设计的"** ❌
   这三个阶段的**接口设计**（Percept 的结构、Plan 的输出格式、Act 的反馈粒度）决定了整个 Agent 架构的上限。糟糕的接口设计会让 Agent 即使有优秀的规划算法也无法有效运作。

4. **"反馈闭环 = 看看执行成功没有"** ❌
   反馈闭环的完整含义是：将执行效果**反馈到下一轮感知中**，形成闭环。如果只是"看看成功没有"而不把结果用于修正下一轮决策，那就不是闭环——只是日志。

5. **"SPA 太基础了，学了 ReAct 就不用学 SPA 了"** ❌
   SPA 是 ReAct 的父模式——理解了 SPA，你就理解了为什么 ReAct 设计成 Thought-Action-Observation 三部分、为什么 Observation 必须来自外部、为什么需要循环。**ReAct 不过是 SPA 在 LLM 上的一个 Prompt 工程实例。**

## 快速总结

- **SPA 是所有 Agent 的元模式**：Sense（感知环境）→ Plan（决定行动）→ Act（执行行动）→ 反馈闭环 → 重复
- **三个阶段各有深层子问题**：Sense 的核心是状态估计和部分可观测性；Plan 的核心是完备性/最优性/实时性的三角权衡；Act 的核心是执行监控和效果验证
- **反馈闭环是 SPA 的灵魂**——没有反馈闭环的 SPA 只是流水线，不是 Agent
- **ReAct = SPA 在 LLM 上的特化实现**——Observation = Sense, Thought = Plan, Action = Act
- **SPA 的三个阶段可以异步、并行、分配不均**——理解这种灵活性是设计高效 Agent 的关键
